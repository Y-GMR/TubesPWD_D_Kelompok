Gambar 2: Arsitektur Manajemen Katalog Master dan Inventaris (CRUD 1)

Alur arsitektur untuk penjelajahan katalog produk, operasi CRUD kategori dan inventaris item oleh admin, pemrosesan media multipart, dan validasi integritas relasional.

1. Lapisan Tampilan Klien 01
Penjelajah Katalog Publik
Menampilkan daftar kartu produk dengan filter kategori (?category_id=) dan pencarian (?search=).
catalog.php
↓
Tampilan Rincian Produk
Halaman detail item menampilkan harga, ketersediaan stok, deskripsi, dan aksi Tambah ke Keranjang.
item_detail.php
↓
Manajemen Kategori Admin
Tabel seluruh kategori dengan modal formulir Tambah, Edit, dan konfirmasi Hapus kategori.
admin/manage_categories.php
↓
Manajemen Inventaris Item
Grid pengelolaan stok produk dengan file picker foto produk, editor stok, dan aksi CRUD.
admin/manage_items.php
2. Pengendali Aksi 02
Aksi CRUD Kategori
Memproses action=create|update|delete. Memvalidasi keunikan nama kategori (2-100 karakter).
actions/crud1_category.php
↓
Aksi CRUD Item Produk
Memproses action=create|update|delete. Memvalidasi category_id, harga >= 0, dan stok >= 0.
actions/crud1_item.php
↓
Saluran Upload Media Aman
Validasi byte biner MIME via finfo_file, penamaan acak random_bytes, simpan ke uploads/items/.
finfo_file() -> uploads/items/
3. Penjaga Hak Akses & Integritas 03
Penjaga Hak Akses Admin
require_admin() mengadang permintaan non-admin dan menghentikan eksekusi dengan status HTTP 403 Forbidden.
require_admin()
↓
Pemeriksaan Hapus Kategori
Kondisi: SELECT COUNT(*) FROM items WHERE category_id = :id
• JUMLAH > 0: Tolak penghapusan, kirim flash error "Kategori masih memiliki produk terkait", redirect 302.
• JUMLAH == 0: Lanjutkan eksekusi DELETE kategori.
↓
Pemeriksaan Audit Hapus Item
Kondisi: SELECT COUNT(*) FROM transaction_details WHERE item_id = :id
• TERCATAT TRANSAKSI: Tolak penghapusan demi menjaga audit historis. Minta admin menyetel stok ke 0.
• TIDAK TERCATAT: Hapus file gambar & eksekusi DELETE item.
4. Lapisan Basis Data & Storage 04
Tabel Relasional: categories
Entitas master kategori. Kolom: id (PK), name (UNIQUE), description, created_at.
sql/schema.sql
↓
Tabel Relasional: items
Foreign key category_id REFERENCES categories(id). Kolom: id, name, price, stock, image_url.
sql/schema.sql
↓
Prepared Statements JOIN
Kueri katalog menggabungkan tabel items dan categories menggunakan parameter binding aman.
SELECT i.*, c.name FROM items i JOIN categories c
↓
Penyimpanan: uploads/items/
Foto katalog produk tersimpan dengan nama unik dan proteksi .htaccess dari eksekusi skrip PHP.
uploads/items/
Alur Permintaan-Respons Utama (Penambahan Item Inventaris dengan Upload Gambar)
1. Kirim Formulir
manage_items.php (POST)
→
2. Rute ke Aksi
actions/crud1_item.php
→
3. Penjaga Admin
require_admin()
→
4. Validasi Tipe MIME
finfo_file() <= 2MB
→
5. Simpan Media ke Disk
uploads/items/hash.ext
→
6. Sisipkan Baris Data
INSERT INTO items
→
7. Redirect Sukses
302 ke manage_items.php
Catatan Gambar 2: Seluruh kapabilitas administratif diisolasi ketat di balik penjaga hak akses require_admin(). Pencegahan baris anak yatim (orphan items) dan foreign key constraints menegakkan integritas basis data relasional. Semua berkas gambar yang diunggah melewati inspeksi biner magic number di sisi server.
