Gambar 1: Arsitektur Siklus Hidup Otentikasi dan Akun Pengguna

Alur arsitektur untuk registrasi pengguna, verifikasi kredensial, middleware session guard, hashing password BCrypt, dan persistensi relasional MySQL.

1. Lapisan Tampilan Klien 01
Formulir Registrasi
Formulir XHTML 1.0 Strict untuk menangkap username, email, nama lengkap, dan password.
register.php
↓
Portal Login
Formulir standar pengiriman kredensial via HTTP POST dengan wadah pesan flash error.
login.php
↓
Tampilan & Edit Profil
Halaman terotentikasi untuk inspeksi profil dan upload foto avatar multipart/form-data.
profile.php
2. Pengendali Aksi 02
Aksi Registrasi Pengguna
Validasi regex ^[a-zA-Z0-9_]{4,30}$, format email, kecocokan konfirmasi password, eksekusi BCrypt.
actions/auth_register.php
↓
Aksi Login Pengguna
Kueri data pengguna via username/email, eksekusi password_verify(), dan regenerasi sesi login.
actions/auth_login.php
↓
Pembaruan Profil & Upload
Validasi tipe MIME via finfo_file, penamaan unik acak, simpan file ke uploads/avatars/.
actions/auth_profile_update.php
↓
Aksi Logout Pengguna
Menghapus array $_SESSION, menghancurkan data sesi, menghapus cookie, redirect 302 ke login.php.
actions/auth_logout.php
3. Penjaga Sesi & Logika Bisnis 03
Pengerasan & Penjaga Sesi
Menetapkan cookie_httponly=1, cookie_samesite=Lax, dan use_strict_mode=1 sebelum session_start().
includes/session.php
↓
Keputusan Verifikasi Kredensial
Kondisi: password_verify($pwd, $user['password_hash'])
• VALID (COCOK): session_regenerate_id(true), simpan user_id & role, redirect 302 sesuai hak akses.
• TIDAK VALID: Simpan $_SESSION['flash_error'], redirect 302 ke login.php.
↓
Kontrol Akses Berbasis Peran
require_login() memverifikasi $_SESSION['user_id']. require_admin() memastikan role === 'admin' atau tolak HTTP 403.
require_login() | require_admin()
4. Lapisan Basis Data & Storage 04
Koneksi Basis Data PDO
Instance koneksi database PDO tunggal (singleton) dengan ERRMODE_EXCEPTION dan charset UTF8MB4.
config/database.php
↓
Tabel Relasional: users
Skema tabel menyimpan id (PK), username (UNIQUE), email (UNIQUE), password_hash, full_name, role, avatar_url.
sql/schema.sql
↓
Eksekusi Prepared Statements
Semua kueri SQL menggunakan parameter binding (SELECT ... WHERE username = :u) mencegah SQL Injection.
PDO::prepare() -> execute()
↓
Penyimpanan: uploads/avatars/
Direktori media terisolasi dengan proteksi penolakan eksekusi skrip melalui file .htaccess.
uploads/avatars/

Catatan Gambar 1: Seluruh interaksi klien-server sepenuhnya mematuhi standar W3C XHTML 1.0 Strict. Password pengguna tidak pernah disimpan dalam format teks biasa dan dienkripsi menggunakan algoritma BCrypt (faktor biaya 10). Konfigurasi parameter keamanan sesi melindungi sistem dari pencurian cookie melalui serangan XSS dan CSRF.
